# hoard Milestone 1 — Core server, R2 storage and local use — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `hoard` binary that serves the Turborepo remote-cache API on localhost, stores artifacts on the local filesystem or a Cloudflare R2 bucket, and keeps the bucket bounded with a lifecycle rule and a size cap.

**Architecture:** One Rust crate (lib + bin). axum serves the API; every backend is an OpenDAL `Operator` wrapped by `Store`; artifacts are stored in the `HRD1` envelope; R2 lifecycle configuration uses `aws-sdk-s3`. Tests run in-process against the `fs` backend and against MinIO for S3/R2 behaviour.

**Tech Stack:** Rust stable (edition 2024), tokio, axum 0.8, opendal (`services-fs`, `services-s3`), aws-sdk-s3 + aws-config (rustls only), clap 4 (derive), serde/serde_json, thiserror, anyhow, tracing, subtle, rand, reqwest (dev), tempfile (dev), MinIO via docker compose, Node 22 + pnpm + turbo (e2e only).

**Spec:** `docs/superpowers/specs/2026-10-14-hoard-design.md`

## Global Constraints

- Cargo package name `keel-hoard`, library name `hoard`, binary name `hoard` (`[[bin]] name = "hoard"`).
- Bind `127.0.0.1` only; never `0.0.0.0`.
- Every route except `GET /_hoard/health` requires `Authorization: Bearer <token>`, compared in constant time (`subtle::ConstantTimeEq`).
- Hash regex `^[a-fA-F0-9]{1,128}$`; anything else → `400`.
- Storage errors never fail a build: GET/HEAD errors → `404`; PUT errors → `200` + `put_errors += 1`.
- Never recompress the artifact body; never buffer a whole artifact in memory (stream).
- Never log the token, R2 secret or any URL containing `sig=` / `X-Amz-Signature`.
- Key format `{prefix}{tool}/{cache_version}/{hash}`; R2 prefix default `cache/` (must end with `/`); `cache_version` default `v1`.
- Envelope: magic `HRD1`, u32 BE header length ≤ 4096, JSON header `{"v":1,"duration_ms":u64|null,"tag":string|null,"size":u64}`, then raw body.
- Defaults: `max-age-days` 7, `max-size` 5GB (powers of 1000), `r2-lifecycle` `auto`, `mode` `read-write`, `port` 0.
- Lifecycle rule ID `hoard-` + prefix with `/` → `-`; abort multipart after 1 day; merge with existing rules, never drop foreign rules.
- Prune throttle marker `{prefix}_hoard/last-prune` (RFC 3339), 24 h.
- `rustls` only; no OpenSSL dependency (static musl builds in milestone 2).

## Review Focus

1. **Turbo sends a PUT for a hash that already exists** (parallel jobs) → `200`, `put_skipped_existing += 1`, the stored object is unchanged. Test in Task 5.
2. **A truncated or foreign object in the bucket** (someone wrote `cache/turbo/v1/<hash>` by hand) → GET is a miss (`404`), `corrupt += 1`, no panic. Test in Task 5.
3. **The bucket already has lifecycle rules from someone else** → our rule is added, theirs survive byte-for-byte. Test in Task 8.
4. **The R2 token cannot change lifecycle rules** → `serve` exits non-zero and stderr contains the exact `npx wrangler r2 bucket lifecycle add …` command. Test in Task 8.
5. **A large artifact (≥ 100 MB) is uploaded** → memory stays bounded (body streamed), round-trip bytes identical. Test in Task 5 (`#[ignore]` locally, run in CI).
